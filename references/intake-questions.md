# 阶段 0 · 前置需求问答（动笔前必须对齐）

> 源自蓝图 P1「大纲引擎」：**先有结构共识，再逐页生产；用户确认前不产生任何页面。**
> 一句话原则：**别一拿到素材就开写。先问清"给谁看、要他做什么、什么风格、几页几分钟"，再动手。**

## 一、为什么必须先问

- 一句话直接吐整份 PPT → 结构随缘、章节失衡、素材关键信息漏掉或编造。
- 返工的最大成本不在"做"，在"做了一版方向错的"。前置 3 分钟问答能砍掉 80% 返工。
- 澄清问题的目的是**帮助决策**（给出候选让用户选），不是**索要信息**（空问"你想怎么做？"）。每个问题都要带默认推荐项。

## 二、必问清单（6 项，缺一项都先补）

按优先级排序，前 4 项是硬门槛，后 2 项可给默认值：

| # | 维度 | 要问什么 | 默认推荐（用户答不上时给） |
|---|---|---|---|
| 1 | **场景类型** | 工作汇报 / 方案推介 / 培训课件 / 融资立项 / 述职 / 产品发布 | 按用户第一句话判断，复述确认 |
| 2 | **听众是谁** | 领导/客户/评委/学员/投资人？他们已知什么、关心什么、可能反对什么 | "假设听众懂业务但不懂细节，重点讲结论与收益" |
| 3 | **核心目标** | 听完后要他**做什么/信什么/批什么**？一句话动作 | "争取资源/拍板/理解进展"三选一引导 |
| 4 | **成功标准** | 怎样算讲成了？（获批预算 / 通过评审 / 学员学会 / 拿到投资） | 转化成可衡量的一句话 |
| 5 | **篇幅时长** | 几页？讲几分钟？ | 汇报默认 10–15 页 / 10 分钟；方案 15–20 页；培训按内容定 |
| 6 | **风格基调** | 正式严谨 / 亲和通俗 / 紧迫有力 / 科技感 | 见 `style-presets.md`，给 2–3 个候选主题 |

## 三、进阶可选（有则更好）

- 有无**企业模板 / 品牌色 / Logo**（有则严格以其为准，见保真守则）。
- 有无**现成素材**：txt / md / docx / pptx / pdf / URL / 一段粘贴文本。
- 有无**必须保留的关键数字、日期、专名**（进保真清单）。
- 有无**参考样例**（"做成某某那样"）——参考样例是最省沟通成本的锚点。
- 是否需要**演讲备注**（每页讲词）。

## 四、怎么问才不烦

1. **一次别超过 4 个问题**，先发最关键的场景/听众/目标/篇幅，其余边做边确认。
2. **给选择题不给填空题**：每个问题附 2–3 个候选 + 标注"(推荐)"，用户可一键采纳或选"其他"。
3. **复述确认**：用户答完，用一句话回述"我理解的是：给 X 看，争取 Y，Z 风格，N 页"，再进入大纲。
4. **合理假设并标注**：信息实在拿不到时，按默认值推进，但明确写出"【待确认】我先假设……"，不静默脑补。

## 五、对齐后的产出（阶段 0 交付物）

一张「需求对齐卡」，作为后续所有步骤的宪法：

```
【场景】季度工作汇报
【听众】分管领导（懂业务、要结论、时间紧）
【目标】争取下季度 AI 项目预算
【成功标准】汇报后领导同意立项
【篇幅】12 页 / 10 分钟
【风格】商务严谨·深蓝主题（见 style-presets.md 主题 B）
【保真清单】营收 34.2%、上线日期 2026-09-01、项目代号"启明"…
【素材】见附件 docx + 2 个数据 URL
【备注】需要逐页演讲词
```

确认这张卡之后，才进入 SLIDE 法的 Story 主线。
