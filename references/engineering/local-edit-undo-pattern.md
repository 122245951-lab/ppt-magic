# 局部编辑与统一撤销：工程实现模式

> 本文给出"圈选/点名局部编辑 + 统一可逆时间线"的实现模式，可直接套用于类 PPT 产品（或任何结构化文档编辑产品）。

## 一、作用域引擎（四态路由）

所有用户指令先路由到四个作用域之一：

| 作用域 | 语义 | 执行器 |
|---|---|---|
| intent | 从零开始：素材 → 大纲 → 生成 | 大纲引擎（P1） |
| deck | 全篇级：换肤 / 删页 / 统一风格 | 计划器：影响清单 + 确认 |
| slide | 当前页级：改文字 / 换版式 / 转图表 | 页执行器 |
| elements | 元素级：只改选中的 / 被点名的元素 | **元素执行器（最小 ops）** |

## 二、元素寻址的两条路径

1. **画布圈选**：渲染层给每个可编辑元素打 `data-el-path`（内容相对路径）与 `data-el-type`。
   - 点击元素 → 选中；Ctrl/Cmd 点击 → 多选切换；空白拖拽 → 框选矩形，松手后与矩形相交的元素全选中。
   - 元素级高亮用 `[data-el-path]` 的 class 切换，不要在渲染组件里硬编码选中态（避免每次重渲染重建）。
2. **对话点名**：无需画布。从指令里提取引用：
   - 引号/书名号内容（「…」「“…”」「'…'」）；
   - 口语引用（"把 X 这句/这条/这段…"）；
   - 序数（"第 N 条 / 第 N 个"），支持中文数字；
   - 命中规则：完全相等 或 长文本互相包含（≥4 字），把候选收敛为 `items[k]` 下标集合。

## 三、元素执行器（最小变更契约）

输入：`els = [{ path, type, text }]` + 当前页 + 指令 → 输出只命中这些路径的 set ops。

```
铁律：
1. 只能对 els 给出的内容路径出 ops；同页其它内容、版式、主题一律不碰。
2. 含数字的元素 → 跳过改写，记录原因（保真 P3）。
3. 文本动作：精简/扩写/正式化/重写（本地确定性或 LLM 均可，动作语义要保持）。
4. 字号动作：元素级 scale（×1.15 / ×0.87，clamp [0.7,2]），不碰全局。
5. 图表动作：只换图表对象（整体替换 chart，避开 type 字段白名单限制）。
```

失败/空结果处理：未选中 → 返回"请先点选或框选"；未命中动作 → 返回说明而非静默。

## 四、统一可逆时间线

目标：**行内编辑、对话操作、批量计划、圈选局部编辑，全部进同一条栈**，多步可逆。

| 字段 | 说明 |
|---|---|
| seq | 自增，撤销按 seq DESC 取最新 |
| kind | slide_patch / deck_apply 等 |
| forward | 本次操作的 ops（用于 redo/审计） |
| inverse | 可回放的原值 ops（用于 undo） |
| undone | 是否已撤销 |

关键实现点与真实踩过的坑：

1. **多步撤销的查询必须排除已撤销行**：
   ```
   SELECT * FROM undo_timeline WHERE deck_id=? AND undone=0 ORDER BY seq DESC LIMIT 1
   ```
   若查全部再靠 `undone` 标记跳出，`steps>1` 只会生效 1 步（第二轮回读到同一条已撤销记录直接 break）。这是最常见的隐藏 bug，冒烟测试用 steps=1 测不出来，必须用"连续 4 步混合操作后 undo×4 回到原文"这种旅程断言。
2. **批量计划用快照 + 差分结合**：`deck_apply` 记录快照 id（整树回退）+ ops（细粒度审计），其余操作一律差分 inverse。
3. **行内编辑也入栈**：用户双击改文字产生的 ops 与 AI 操作同栈，保证"AI 编辑与手动编辑交替不打架"。
4. 页面删除等结构性 op（insert/remove/reorder）需要生成反操作（insert↔remove、reorder 互换 from/to）。

## 五、验收断言模板（最有力的断言是"其余不变"）

```js
// 只改 items[1]：改前深拷贝整页，执行后逐字段断言
ok(after.items[1].text !== before.items[1].text)          // 目标变了
ok(after.items[0].text === before.items[0].text)          // 邻居没动
ok(after.items[2].text === before.items[2].text)
ok(after.title === before.title)
ok(JSON.stringify(ids) 不变)                                // 元素 id 未被重建
// 撤销
undo×4 后 items 全部 === 最初原文
```

## 六、与 AI 对话的边界

- 本地确定性引擎（离线、毫秒）保证基线体验；接入 LLM 后，重写类动作换模型、保真跳过与最小化 ops 的"守卫"仍然由引擎做——**模型负责表达，引擎负责不变量**。
- 模型 Key 解析顺序：个人 BYOK → 管理员全局默认 → 本地引擎；任何人拿他人 Provider id 访问一律 404。
