# P1–P5 五根能力支柱详解

> 每根支柱按四个视角展开：**解决什么失败模式 → 抽象定义 → 落地机制（真实实现示例）→ 验收口径 → 自查问题 → 常见误区**。复刻产品时逐根对表。

## P1 大纲引擎（Outline Engine）

- **失败模式**：一句话直接吐整份 PPT —— 结构随缘、章节失衡、素材里的关键信息漏掉或编造。
- **抽象定义**：先建立"结构共识"，再逐页生产。生成的前一步是"大纲评审"，用户确认前不产生任何页面。
- **落地机制**：
  1. 素材摄取（粘贴文本 / txt / md / docx / pptx / pdf / URL），抽取为带段落号的原文（保留数字与专名，供保真锚定）。
  2. 深挖大纲：标题 / 副题 / 分节（heading + summary + keyData + points），对含糊处给出澄清问题与候选句式。
  3. 采用大纲后才逐页生成；生成节奏可流式下发（页级进度）。
- **验收口径**：生成页数、章节顺序、关键数字与大纲一致；用户确认前文档库为空。
- **自查问题**：素材里的数字有没有进页面？大纲能不能被"直接采用"而不是再抽一版？澄清问题是帮助决策还是索要信息？
- **常见误区**：把"生成大纲"做成装饰性中间步，用户点掉后仍自由发挥；或用 LLM 直接产页面，无素材锚点，导致保真无从谈起。

## P2 锁定版式库（Locked Layout Library）

- **失败模式**："AI 排版"= 自由画布/自由 CSS —— 同一指令每次输出都不一样，字体字号能跑飞，PPT 变成 HTML 弹窗。
- **抽象定义**："会排版"不是生成能力强，而是**输出空间被约束在专业枚举内**。视觉永远从页型 × 版式 × 主题 × 密度/栏数/媒体占比等档位里"夹取"，永不产生任意值（任意 px / 任意颜色 / 任意坐标）。
- **落地机制**：
  - 页型（cover/bullets/two-column/quote/section-divider/stat/timeline/table/flow/hero/matrix/roadmap/closing）→ 每页型若干锁定版式（id、支持栏数、媒体位、容量预算）。
  - 视觉指令走统一映射：请求不匹配当前版式能力时，**在同页型内自动切换到支持该能力的锁定版式**（例：要 2 栏而当前版式只支持 1 栏 → 换成 bullets-two-col），而不是发明新布局。
  - 字号/密度/对齐等全部落到档位函数（clamp、moveDensity、nearestMediaShare），输入任意自然语言也只会到达最近合法档位。
- **验收口径**：对任意 100 条视觉指令，结果 `variant` 恒在版式库枚举内、`design` 恒在合法域内；没有一条产生"任意 px"。
- **自查问题**：你的产品有没有"输出空间枚举"？字号能直接写 17px 吗？想 2 栏但版式不支持时，系统是换版式还是硬塞？
- **常见误区**：把"好看模板库"当版式约束（模板只是素材，约束是运行时枚举）；或让用户自由拖拽坐标，把"AI 排版"降级成"AI 填内容"。

## P3 保真闸门（Fidelity Gate）

- **失败模式**：LLM 改写时把"营收 34.2%"改写成"约三成多"、"2026-09-01"被挪位 —— 对财报/银行/汇报场景是致命错误。
- **抽象定义**：数据是不可妥协的：**可改说法，不改数字**。以"数据指纹比对 + 分级闸门 + 溯源还原"把保真从提示词约束升级为机制保证。
- **落地机制**：
  - 指纹抽取：数字（含百分比/小数/万亿单位）、日期、专名。改写、生成、图表转换全程留指纹。
  - 三级闸门：自由 / 标准 / 严格（严格=含数字句子一律零改写）。
  - 差异呈现：疑似改动内联标红，hover 显示"原文 + 来源段锚点"，一键还原。
  - 改写器铁律：目标文本含数字 → 跳过并在结果注明原因。
- **验收口径**：对含数字句子发起"改短/重写"，diff 数为 0 且给出跳过说明；全篇扫描数字保真率 100%。
- **自查问题**：你的 LLM 调用里，保真是"prompt 里写了一句"还是"有指纹比对兜底"？用户能不能看到"哪里被改了、原文是什么、一键还原"？
- **常见误区**：认为"模型没那么笨"；或用归一化提示词但无机器校验，回归一次就漏。

## P4 局部精修（Element-scoped Editing，指哪改哪）

- **失败模式**：想改第 4 页一条要点，系统把整页重新生成 → 其余内容被无谓改写、排版被破坏。
- **抽象定义**：编辑作用域最小化。所有可编辑元素用**内容路径**寻址（如 `items[2].text`），自然语言（含圈选）先映射到元素路径集合，再只对这些路径产生最小变更（ops）。
- **落地机制**：
  - 画布元素带 `data-el-path` + 类型标签；点选 / Ctrl 多选 / 拖框选（相交即选中）都收敛为路径集合。
  - 对话点名：消息引用原文（「…」/“把 X 这句”）或序数（第 N 条）→ 自动定位，无需画布。
  - 执行器对选中元素只出 set ops；含数字元素按 P3 跳过；同页其余内容 JSON 级不动。
  - 元素级字号用每元素 `scale` 字段（如 1.15 倍），不碰全局字号档。
- **验收口径**：改 items[1]，断言 items[0]/items[2]/标题/页脚 JSON 完全相等；元素 id 不被重建。
- **自查问题**：你能不改动整页、只改"第二段的第三个数字旁的那句"吗？怎么把用户意图映射到最小路径集合？
- **常见误区**：以"重新生成这一页"代替局部编辑；或让 LLM 直接返回整页 JSON（会悄悄重排其它内容）。

## P5 可信操作（Trustworthy Operations）

- **失败模式**：批量操作（换肤/删页/转图表）直接执行，毁了一页才发现；撤销只能回到"上一步 AI 操作"，手动编辑不在此列；Key 明文落库。
- **抽象定义**：每一步都可解释、可回退、可追责。全篇级操作先给**影响清单 + 破坏性标记**；一切变更（行内编辑 / 对话操作 / 批量计划 / 圈选局部编辑）进入**同一条可逆时间线**。
- **落地机制**：
  - 计划器：批量操作产出"影响页清单 + 摘要 + 破坏性标记"，服务端保留 30 分钟，确认后才事务应用（快照）。
  - 统一时间线：每条记录 forward ops 与 inverse ops；多步撤销逐条回放 inverse。
  - 账号与 Key：RBAC、多租户隔离（越权 404）、模型 Key AES-256-GCM 加密落库 + 只回掩码；个人 BYOK 与全局默认分层。
- **验收口径**：连续 4 次混合操作（含手动编辑）后 undo×4 能回到最初原文；个人 Provider 对他人访问一律 404。
- **自查问题**：手动拖拽/双击编辑进没进撤销栈？"多步撤销"是否真的多步（查实现是否排除已撤销行）？删页前有没有先问？
- **常见误区**：只给"撤销对话"不给"撤销手改"；快照代替差分（快照占存储且不可细粒度回退）；undo 查询不排除已撤销记录导致 steps>1 只生效 1 步（真实踩过的坑）。
